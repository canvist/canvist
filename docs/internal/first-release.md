# First release readiness

Audit date: 2026-11-03. Audited main at `70c936d` and release PR [#180](https://github.com/canvist/canvist/pull/180), whose SDK dry run used `9162277c11bba35467b5ff01c959c2621b898607`.

## Build status

There is no GitHub release yet. This does not mean the source cannot build. The latest main commit passed Rust CI, web, headless JS, canvas, native, desktop, Dart, and the other build workflows. Its [testkit push run](https://github.com/canvist/canvist/actions/runs/41036479509) failed on Android; later nightly runs passed on the same SHA. The daemon held its shared mutex across an idle five-second long poll while its health check allowed only two seconds. That could cause a healthy daemon to be mistaken for a dead one and competing device runs to start. The fix releases the mutex before waiting and registers the notification before checking for work. The regression test fails on the old code and passes on the fix.

The [SDK publish dry run](https://github.com/canvist/canvist/actions/runs/41038585747) successfully built all five npm packages and their WASM variants, checked exported files in their tarballs, packaged the Rust crate graph, built the Apple XCFramework and published Android to Maven Local. The [app dry run](https://github.com/canvist/canvist/actions/runs/41038581730) built both Docker images. These are build checks, not successful registry authentication or publication.

## Build the browser SDK from source

Use a fixed checkout SHA, Node 24, the Rust toolchain in `rust-toolchain.toml`, and wasm-pack 0.15.0 (the version used by the successful SDK dry run). Run from the repository root:

```sh
rustup toolchain install
rustup target add wasm32-unknown-unknown
CARGO_PROFILE_RELEASE_BUILD_OVERRIDE_STRIP=none cargo install wasm-pack --version 0.15.0 --locked
bash tools/release/build_web.sh
```

The shared script runs `npm ci`, builds headless, web, React, Vue and canvas in dependency order, then checks the exported files in every npm tarball. Publication uses this same script. It leaves generated WASM and `dist` directories locally, without committing them. A fresh macOS build also exposed Rust 1.96/macOS 27 stripping host proc-macro metadata (`E0463` for `rustversion`). The release profile now keeps host build tools unstripped via `build-override`, following [the upstream issue](https://github.com/rust-lang/rust/issues/157750). Final WASM optimization is unchanged. This gives consumers a repeatable build procedure; it does not promise byte-for-byte identical binaries across host platforms. Until a real release ships, Slopper must use built source packages rather than the registry placeholders. Once released, verify Slopper can install the tarballs in a clean project without workspace links.

Local validation of the fixes: the full shared build completed on macOS with all five npm tarball export checks passing. The seven web unit tests, 23 testkit unit tests, 21 typing/extension integration tests (headless and loopback targets), four workflow provenance tests, Clippy correctness checks, formatting and shell checks passed. The daemon regression was also run against the original code and failed as expected. Device execution of the fix still needs GitHub CI; the local tests prove the lock contention without requiring an emulator.

JSR is excluded from the release targets. The TypeScript packages publish to npm.

## Trusted publishing audit

GitHub's `publisher` environment exists, requires approval by `ifiokjr`, and permits only the tag patterns `v*` and `app/v*`. The publishing jobs request `id-token: write`. Cargo and npm configuration in `monochange.toml` names repository `canvist/canvist`, workflow `publish.yml`, and environment `publisher`. Node 24 is installed and npm token authentication is unset for publication. These are the repository side of trust only.

**Registry-side trust is not confirmed.** The archived `publish-readiness.json` reports `manual_verification_required` for every enabled npm and crates.io package, even though each package's outer status is `ready`. Package existence and `npm publish --dry-run` do not prove OIDC authentication. The crate API returned HTTP 403 from this machine; npm's publisher settings require owner access. Do not present a green dry run as confirmation that all targets are configured.

## Before merging the first release PR

1. Decide the supported first-release targets. A browser/Rust release can proceed independently of mobile/desktop, but the notes must clearly state which integrations remain source-only. Currently Android can silently publish only to Maven Local, pub.dev can be skipped, and Swift assets alone do not make the repository installable through SwiftPM.
2. Complete and record the owner-side registry checks above. Do not weaken `publisher` protections to bypass missing trust.
3. Rebase/refresh the release PR after the build fix and run the SDK and app dry runs on that exact commit. PR #180 currently plans SDK `0.2.0`; confirm that version and its package list are intended.
4. Smoke-test packed npm artifacts in an isolated consumer: React editor mount, WASM loading, fonts, typing and SSR imports without local workspace dependencies. Test any other advertised target using only its published/packed artifacts.
5. Review tag protection, release notes, licensing and installation documentation. Ensure real SDK publication cannot finish green while an advertised target was skipped or published only locally.
6. Merge the release PR only when ready for irreversible registry publication, approve the `publisher` jobs, and verify the published versions, npm provenance, GitHub assets and clean consumer install. Package publication is not transactional: on a partial failure, inspect which versions exist and resume the remaining publications without changing already-published contents.

This audit publishes no packages, tags, or releases and changes no registry settings.
